## 0. Статус и область действия

[FACT] Данный документ является нормативным.
[DECISION] Все документы корпуса ОБЯЗАНЫ соответствовать настоящей спецификации.
[DECISION] Любое отклонение допустимо только при явной фиксации и обосновании.
[FACT] Спецификация применяется ко всем документам в `docs/`, независимо от автора.

## 1. Классы документов

Каждый документ ОБЯЗАН иметь поле `class` во front matter.

### 1.1 Канонический список классов

| class | Назначение |
| ----- | ---------- |
| ssot | Source of Truth: базовое описание мира |
| override | Переопределение/уточнение SSOT |
| baseline | Исполняемые дефолты среды |
| report | Аналитические входные исследования |
| canon | Консолидированный канон |
| plan | План/каркас без художественного текста |
| scene | Сценический материал |
| spec | Нормативная спецификация |
| registry | Реестры (UNKNOWN, индексы и т.п.) |
| idx | Навигационные индексы |

## 2. Статусы утверждений (Semantic Markers)

### 2.1 Канонический список статусов

[DECISION] Допустимы ТОЛЬКО следующие статусы:

~~~text
[FACT]        — утверждение, принятое как истинное в рамках мира
[ASSUMPTION]  — допущение, используемое для моделирования
[PROJECTION]  — результат экстраполяции или сценарного расчёта
[UNKNOWN]     — осознанная неопределённость
[DECISION]    — редакционное или каноническое решение
[FORBIDDEN]   — явно запрещённое состояние
[DEFAULT]     — значение по умолчанию (baseline)
~~~

Других статусов **не существует**.

### 2.2 Синтаксис статусов (ОБЯЗАТЕЛЬНО)

[DECISION] Статус пишется:

- в **квадратных скобках**
- **ЗАГЛАВНЫМИ буквами**
- **в начале строки или пункта списка**

#### Корректно

~~~markdown
[FACT] Энергосистема инерционна.
- [ASSUMPTION] Переход займёт несколько поколений инфраструктуры.
~~~

#### Запрещено

~~~markdown
FACT: Энергосистема инерционна
- FACT Энергосистема инерционна
~~~

## 3. Допустимые статусы по классам документов

| class | Разрешены | Запрещены |
| ----- | --------- | --------- |
| ssot | [FACT] [ASSUMPTION] [PROJECTION] [UNKNOWN] | сюжет |
| override | [FACT] [DECISION] | новые домыслы |
| baseline | [FACT] [DEFAULT] [FORBIDDEN] | [ASSUMPTION] |
| report | [FACT] [ASSUMPTION] [PROJECTION] | канон |
| canon | [FACT] [DECISION] | новые факты |
| plan | [DECISION] | факты о мире |
| scene | ❌ статусы запрещены | любые статусы |
| spec | [FACT] [DECISION] | художественный текст |
| registry | [FACT] [DECISION] | сцены |

[DECISION] Использование статусов вне разрешённого списка — ошибка.

## 4. Атомарность утверждений

[FACT] Одно утверждение = одна логически проверяемая мысль.

### 4.1 Запрещено

~~~markdown
[FACT] Энергосистема инерционна и потому переход медленный и вызывает кризисы.
~~~

### 4.2 Корректно

~~~markdown
[FACT] Энергосистема инерционна.
[PROJECTION] Переход к новым источникам энергии растянут по времени.
[ASSUMPTION] Длительный переход увеличивает вероятность локальных кризисов.
~~~

## 5. Причинность (CAUSE → MECHANISM → CONSEQUENCE)

[DECISION] Причинность ОБЯЗАНА быть явной в аналитических документах.

### 5.1 Допустимые формы

~~~markdown
CAUSE → MECHANISM → CONSEQUENCE
~~~

или

~~~markdown
[FACT] CAUSE: …
[FACT] MECHANISM: …
[PROJECTION] CONSEQUENCE: …
~~~

### 5.2 Запрещено

- описывать следствие без причины;
- использовать формулировки «просто происходит», «очевидно».

## 6. Заголовки и иерархия

### 6.1 Нормативная структура

~~~markdown
# Документ
## Раздел
### Подраздел
#### Локальная структура
~~~

[DECISION] Пропуск уровней запрещён.

## 7. Списки

[FACT] Списки используются только для перечислений.

### 7.1 Разрешено

~~~markdown
- элемент
- элемент
~~~

### 7.2 Запрещено

- логика внутри списка;
- смешивание нескольких утверждений в одном пункте.

## 8. SCENE-документы (особый режим)

[DECISION] В документах класса `scene`:

- ЗАПРЕЩЕНЫ статусные маркеры (`[FACT]` и т.п.);
- запрещены объяснения устройства мира;
- сцена ПОКАЗЫВАЕТ, но не утверждает.

[FACT] Валидация сцен происходит через CANON и BASELINE, а не текст сцены.

## 10. UNKNOWN и реестры

[DECISION] Любой `[UNKNOWN]` ОБЯЗАН:

- быть зарегистрирован в REG-UNKNOWN;
- иметь тип (`TO_RESEARCH`, `CANON_DECISION`, `DEFERRED`, `TO_AVOID`);
- иметь путь закрытия.

## 11. Lint-правила (норматив)

Минимальные требования:

- статус вне квадратных скобок → ERROR
- статус в `scene` → ERROR
- `[UNKNOWN]` без записи в реестре → WARNING
- абзац без статуса в `ssot` → WARNING

## 12. Принцип приоритета

[FACT] При конфликте действует приоритет:

~~~text
override → ssot → baseline → canon → plan → scene
~~~
